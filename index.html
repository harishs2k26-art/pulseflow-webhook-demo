Understand a delivery before trusting its side effects.

Explore realistic event envelopes, inspect signed headers and simulate receiver behavior in a browser-only lab. No public webhook endpoint or production PulseFlow service is operated here.

GitHub Pages is static hosting. This inspector does not receive Internet requests, proxy traffic or send your payload elsewhere. Use invented values only; never enter real signing secrets or customer data.

What the lab demonstrates

Exact-byte signatures

Sign a timestamp plus the raw JSON body with HMAC-SHA256. Change whitespace after signing to see why parsing and reserializing before verification is unsafe.

Failure-aware delivery

Choose a 200, 429 or 500 receiver response. Distinguish signature rejection from an authenticated receiver that cannot process the event yet.

Idempotent replay

Repeat a successfully processed event ID. The local receiver acknowledges the duplicate without applying its pretend side effect again.

Reference delivery lifecycle

  1. An event is accepted and assigned a stable logical event ID.
  2. A delivery attempt signs the current timestamp and unmodified body.
  3. The receiver validates freshness and signature before parsing trusted fields.
  4. A durable inbox deduplicates by workspace and event ID before side effects.
  5. A successful acknowledgment ends delivery; a transient failure may be retried.

The fictional schedule allows up to seven attempts at event ages 0, 5 seconds, 1 minute, 5 minutes, 30 minutes, 2 hours and 24 hours. These are target ages from the first attempt, not delays added to one another. The browser lab performs only manual attempts and implements no background scheduler.

Before building a real receiver

Set a body-size limit before parsing, validate timestamps against a synchronized clock, compare HMAC values safely and persist accepted work before acknowledging it. Never execute shell commands or render HTML derived from untrusted event fields.
