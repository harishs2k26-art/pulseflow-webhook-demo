Event library / schema 2026-10-01

Small envelopes. Clear operational meaning.

These synthetic examples contain no customer data and can be pasted into the local inspector. Field names are part of the protocol and remain stable across localized interfaces.

Workflow succeeded

{
  "id": "evt_demo_1001",
  "type": "workflow.succeeded",
  "schema_version": "2026-10-01",
  "occurred_at": "2026-11-14T07:00:00Z",
  "workspace_id": "ws_demo",
  "data": {
    "run_id": "run_checkout_42",
    "workflow": "checkout.fulfillment",
    "duration_ms": 184,
    "step_count": 4
  }
}

A success event means the logical workflow reached its terminal successful state. It does not mean every notification has already been delivered. Use the run ID to correlate with traces and the event ID to deduplicate downstream processing.

Workflow failed

{
  "id": "evt_demo_1002",
  "type": "workflow.failed",
  "schema_version": "2026-10-01",
  "occurred_at": "2026-11-14T07:01:00Z",
  "workspace_id": "ws_demo",
  "data": {
    "run_id": "run_checkout_43",
    "workflow": "checkout.fulfillment",
    "duration_ms": 5000,
    "error": {"code": "UPSTREAM_TIMEOUT", "retryable": true},
    "failed_step": "inventory.reserve"
  }
}

The retryable hint describes the upstream failure, not permission to execute a business action twice. The workflow owner decides whether a new run is safe. Never include a raw exception containing credentials or personal details in the event.

API threshold breached

{
  "id": "evt_demo_1003",
  "type": "api.threshold_breached",
  "schema_version": "2026-10-01",
  "occurred_at": "2026-11-14T07:02:00Z",
  "workspace_id": "ws_demo",
  "data": {
    "route": "POST /v1/orders",
    "metric": "p95_latency_ms",
    "observed": 820,
    "threshold": 500,
    "window_seconds": 300,
    "sample_count": 1200
  }
}

Use route templates, not raw URLs containing user identifiers or query-string secrets. Interpret a threshold in the context of the observation window and sample size; a single slow request is not equivalent to a sustained percentile regression.

Envelope field reference

FieldRuleConsumer behavior
idStable logical event identifierKeep unchanged on replay
typeDocumented dotted event nameRoute known types; safely handle unknown ones
schema_versionDate-based envelope contractReject unsupported breaking versions
occurred_atUTC event time ending in ZDo not confuse with delivery signing time
workspace_idTenant context, independently authorizedInclude in deduplication keys
dataEvent-specific JSON objectValidate fields before side effects

Evolution and replay

Consumers should tolerate additive fields while validating the fields they use. A signature proves possession of a shared secret, not semantic validity. Deduplicate transactionally, retain inbox IDs at least 72 hours for the reference delivery window and treat replay as another attempt of the same event.
